🔒 1. Justificación de las 3 Características Críticas

Para un sistema de misión crítica como AeroControl Ops, donde se coordinan vuelos y aproximación, los errores de software implican riesgos operacionales directos:

  • Seguridad (Security): Porque nadie ajeno a la torre de control debe poder alterar un plan de vuelo, modificar puertas o encubrir incidentes.
  • Fiabilidad (Reliability): Porque el aeropuerto opera 24/7 ininterrumpidamente y el sistema no puede perder sesiones ni estado ante reinicios o microcortes.
  • Protección (Safety): Porque el software debe prevenir activamente catástrofes físicas (evitar aterrizajes en pistas clausuradas o colisiones de aviones en puertas).

🚀 3. Top 5 Mejoras Prioritarias para Pase a Producción

  1. Seguridad de Contraseñas: Reemplazar SHA-256 por bcrypt (factor 12) y añadir Rate Limiting (máximo 5 intentos en 15 min) en el login.
  2. Pruebas Automatizadas: Implementar una suite de pruebas unitarias automáticas con node:test o vitest para las validaciones de vuelos y login.
  3. Persistencia de Sesiones: Migrar las sesiones en memoria (new Map()) a una tabla en MySQL o Redis para soportar escalabilidad horizontal.
  4. Validación de Safety en Backend: Bloquear en POST /api/vuelos cualquier autorización si la pista o puerta asignada se encuentra en estado "Cerrada" o "Mantenimiento".
  5. Modularización de Código: Desacoplar el archivo monolítico index.html (4,392 líneas) en styles.css, app.js y módulos independientes.

🎙️ 4. Guion Rápido y Respuestas Clave para la Defensa

"Evaluamos el sistema bajo ISO/IEC 25010:2023. El software destaca con cumplimiento total en Adecuación Funcional, Usabilidad, Detección de Conflictos en Radar e Inmunidad a Inyección SQL con Prepared Statements. Como oportunidad de mejora para una fase de producción, identificamos la necesidad de incorporar pruebas automatizadas (Testabilidad) y migrar el hash de contraseñas a bcrypt con salting."
